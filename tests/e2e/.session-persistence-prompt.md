# E2E Test Generation: Session Persistence Across Page Reload

**Risk (from context/foundation/test-plan.md, Risk #4):**  
Review session loses progress mid-session; user must restart. Session state (card_order, current_index, answered_count) must survive browser refresh.

**Observable business outcome:**  
User reviews cards, answers 2, refreshes the browser, and session resumes at card 3 (not restarted at card 1).

**Flow:**

1. **Setup:**
   - Authenticated user exists (use `storageState`).
   - Create a deck with 5 cards via the deck API.

2. **Action:**
   - Navigate to `/review` page.
   - Click "Start Review" button to begin session.
   - Verify first card (card #1) is displayed.
   - Click "Reveal" to show the back.
   - Click one of the rating buttons (e.g., "Good") to answer card #1.
   - Verify card #2 is now displayed.
   - Click "Reveal" for card #2.
   - Click "Good" to answer card #2.
   - **Refresh the page** (`page.reload()`, NOT `F5` or manual navigation).
   - After reload, page should load and auto-resume the session.

3. **Assertion:**
   - Page shows card #3 (not card #1 — session resumed, not restarted).
   - Card #3's front content matches the 3rd card in the original deck.
   - No error message appears.

4. **Real vs Mocked:**
   - **Real boundaries:** Auth (stored state), routing (`/review` page), API calls (`/api/review/current`, `/api/review/session`, `/api/review/answer`), DB (session row with updated card_order and current_index).
   - **Mocked boundaries:** None — this is a full integration test. No external APIs to mock.

5. **Test data uniqueness:**
   - Deck name: `Persistence Test Deck ${Date.now()}` (timestamp suffix to avoid collision in parallel runs).
   - Use the same session ID across the refresh to verify durability.

6. **Cleanup:**
   - Delete the test deck after the test completes.

3. **Revert immediately**; never commit the break.
